# 问题追踪规则

## 核心原则

审查代码时发现的任何问题，如果不在当前任务范围内，必须立即记录到 `.kiro/issues.md`。不要浪费算力重复发现同一个问题。

## 何时记录

- 阅读源文件时发现 bug、安全漏洞、代码质量问题
- 执行任务时发现关联文件中的已有缺陷
- 运行测试时发现非当前任务导致的失败
- 审查设计文档时发现与实际代码不一致的地方

## 记录格式

```markdown
### {优先级} ISSUE-{编号}: {一句话描述}
- **文件**: `{文件路径}`
- **描述**: {具体问题}
- **影响**: {对用户或系统的影响}
- **发现于**: {spec名称或任务上下文} ({日期})
```

优先级：
- 🔴 Critical — 安全漏洞或数据损坏
- 🟡 Major — 功能缺陷或架构问题
- 🟢 Minor — 代码质量、性能

## 修复后

将状态改为 ✅ Fixed，注明修复的 spec 或 commit：
```markdown
### ✅ ISSUE-001: ...
- **修复于**: kong-authn-authz-fix 任务 5.3 (2026-03-30)
```
