# Portal 设计 parity — Developer Workstation → User Portal

**核心原则：** Developer Workstation 中设计师看到的表单/子表/布局/Portal Display 配置，在 User Portal 运行时 MUST 呈现为**同一套 UI 结构**（字段顺序、子表嵌套、Link Form、表格下列表等）。不允许「设计器能预览、门户静默省略」的捷径。

**Form Preview = 设计稿运行时：** 表单设计器工具栏打开的 **Form Preview** 弹窗（`FormDesigner` → `FormPreviewItems` / `SubTableField` 预览）就是 **Developer Workstation 所设计页面的标准渲染结果**。它与 User Portal 不是两套 UI——**Preview 弹窗与 Portal 运行时 MUST 一致**；改 Preview 或改 Portal 任一侧时，另一侧 MUST 同步对齐，直至两边视觉与结构相同。

本原则是现有 Portal 契约的**总纲**；下列专项规则是其组成部分，不得与之冲突：

| 组成部分 | 位置 / 说明 |
|---|---|
| **Form Preview（设计侧基准）** | `FormDesigner.vue` 预览弹窗 — `FormPreviewItems`、`SubTableField`（含 To Do / My Requests 双 tab）；**即设计页面的 canonical 渲染** |
| Portal Display 模式 | `formRendererHelpers.ts` — `assigneeTodo` / `initiatorRequest` / `mergeSubTablePortalViewsForRuntime` |
| 主表单渲染（Portal 侧） | `FormRenderer.vue` — 画布 `rule` + `subTableBindings` + `viewContext` |
| Preview ↔ Portal merge 对齐 | `mergePortalViewsForPreview`（DW）与 `mergeSubTablePortalViewsForRuntime`（Portal）MUST 同一语义 |
| **My Request × MI 子表数据** | `portal-mi-subtable-my-request.mdc` — 发起人全案 vs 办理人切片；file-only 附件；**#1441 Details 弹窗 id/sub_task_id** |
| **Form Preview FK/PK 运行时** | `form-preview-fk-pk-runtime.mdc` — **Save 时** PK 分配（主表→FK→子表）、deferPkAllocationUntilSave、MI seed/allocate 分流、**§6.5 My Request Details 弹窗**、回归缺陷表 §8 |
| **待办节点 Action 按钮** | BPMN `actionIds` → `TaskActionService` → `TaskActionBar.vue`（见下文 §待办 Action 按钮） |
| **截图验证（必跑）** | `frontend-screenshot-verification.mdc` — 改可见 UI 后 Playwright 截图至 `verification-screenshots/`，**禁止验证后删除** |

## 待办 Action 按钮（BPMN 绑定）

Designer 在 userTask 上配置的 **Actions**（`custom:actionIds`，值为 `dw_action_definitions` 整数 ID）MUST 在 Portal 待办详情底部展示。

**解析链：** workflow-engine 返回 `actionIds` → `TaskActionService.getTaskActions` → `sys_action_definitions.findAllById` → 缺失时 **`findFromDwByIds`**（`ActionDefinitionRepository`）。

| 要点 | 说明 |
|---|---|
| DW 列名 | `dw_action_definitions` 描述列为 **`display_name`**（非 `description`）；native SQL MUST **`d.display_name AS description`** 映射到 `ActionDefinition.description` |
| 前端展示 | `TaskActionBar`：`actions.length > 0` → 自定义按钮；`actions == null` → 默认 Approve/Reject；**`actions === []`** → 两者皆不显示（仅转办/委派/催办） |
| 典型症状 | 节点已绑 Action 但底部无按钮 + 日志 `column d.description does not exist` → 修 `findFromDwByIds` |

## 必须遵守

1. **结构 parity**：画布 `rule` 中的每个 `subTable`、`lookup`、`card`、tab 布局，在 Portal 对应视图（待办 / 我的申请 / 流程发起 / Link Form 弹窗 / 表格下内联表单 / MI Detail 弹窗）中 MUST 有等价渲染路径，不得仅用 `FieldRenderer` 跳过 `subTable` 节点。
2. **数据 parity**：子表行来自 `binding.data`、`__subTables__` 嵌套、流程变量三者之一或组合；hydrate/enrich 逻辑 MUST 与 `tasks/detail.vue` / `applications/detail.vue` 主路径一致，不得在新弹窗/内联组件中单独写「简化版取数」。
3. **Portal Display parity**：`configJson.subTablePortalViews[bindingId]` 与画布 `props.portalViews` 的 merge 结果 MUST 与 **Form Preview 弹窗**中同 binding 的展示一致（`mergeSubTablePortalViewsForRuntime` ↔ `mergePortalViewsForPreview`）。
4. **Schema 回退 parity**：同一 Function Unit 内多表单共享 `tableId` 时，MUST 使用 `resolveSubTableSchemaByTableId`（及 `deriveColumnsFromRelationFieldDefinitions`）回退，避免 copied binding 空列导致子表不渲染。
5. **嵌套子表**：子 Form（subForm / Link Form 目标 / MI 子任务表单）内的 `subTable` MUST 传入完整 `sub-table-bindings` + `linked-sub-table-bindings`，与主表单 `FormRenderer` 相同。

## 新增 Portal UI 路径时的检查清单

- [ ] 是否复用了 `FormRenderer` 或与其等价的 `SubTableField` + bindings 组合？
- [ ] `subTable` 节点是否因 `FieldRenderer` / 扁平内联表单而被跳过？
- [ ] `viewContext`（`assigneeTodo` / `initiatorRequest`）是否正确？
- [ ] 设计师改了 Portal Display 后，**Form Preview 弹窗**与 Portal 是否仍同一 merge 函数、同一布局？
- [ ] 新增/修改 Preview 组件时，Portal 对应路径是否已同步（反之亦然）？
- [ ] 是否与 `tasks/detail.vue` 行为对齐（My Request 见 `applications/detail.vue`）？
- [ ] **My Request Details 弹窗（#1441）**：未处理参与者 `id` 空、`sub task id`=父 `id_idw`？已填写行 `id`=UUID？发起人 Sub Task 无 allSlices 污染（3 条）？见 `form-preview-fk-pk-runtime.mdc` §6.5、`verify-myrequest-details-modal.mjs`
- [ ] BPMN 节点绑定的 **Action 按钮**是否经 `TaskActionService` 正确解析并在 `TaskActionBar` 展示？`findFromDwByIds` 是否用 `display_name AS description`？

## 禁止

- 在 Link Form 弹窗、SubTableInlineForm、MI Detail 弹窗中**故意不递归**嵌套子表（除非产品明确废弃该设计并同步改 Designer Preview）。
- 新建仅面向 Portal 的「简化渲染器」且结构与 Designer `rule` 不一致。
- 让 Form Preview 弹窗与 User Portal 出现**结构性分叉**（Preview 能看到的子表/嵌套/Link Form，Portal 看不到，或反之）。
- 仅在 Designer 配置 binding 级 Portal Display 却只在画布节点读配置（或反之）导致 Preview 与 Runtime 分叉。
