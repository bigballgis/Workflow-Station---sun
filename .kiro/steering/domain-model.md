# 领域模型 — 统一语言

使用以下精确术语，不要发明同义词。保持代码、API、UI、文档中的命名一致。

## 核心领域概念

| 领域术语 | 英文标识 | 所属模块 | 说明 |
|---------|---------|---------|------|
| 功能单元 | `FunctionUnit` | developer-workstation | 可视化设计的最小业务单元 |
| 表单设计 | `FormDesign` | developer-workstation | 拖拽式表单设计器产出 |
| 流程定义 | `ProcessDefinition` | workflow-engine | Flowable BPMN 流程模板 |
| 流程实例 | `ProcessInstance` | workflow-engine | 运行中的流程 |
| 任务 | `Task` | workflow-engine / user-portal | 待办工作项 |
| 决策表 | `Decision` | developer-workstation | DMN 决策规则 |
| 关联表 | `RelationTable` | developer-workstation | 业务数据表（字段+行） |
| 用户 | `User` | admin-center | 平台账户 |
| 角色 | `Role` | admin-center | 权限分组 |
| 权限 | `Permission` | admin-center | 细粒度访问控制 |
| 数据字典 | `Dictionary` | admin-center | 系统级枚举/选项配置 |

## 跨上下文通信

- 服务间调用通过 `client/` 包中的 REST Client（非直接依赖）
- 事件通知通过 `platform-messaging` (Kafka)
- 共享数据结构通过 `platform-common` 中的 DTO

## 命名红线

- `FunctionUnit` 不要写成 `Function`、`Unit`、`Module`、`Block`
- `RelationTable` 不要写成 `DataTable`、`BusinessTable`、`CustomTable`
- `FormDesign` 不要写成 `FormTemplate`、`FormSchema`、`FormDefinition`
- 表名前缀必须匹配: `dw_`(developer), `ac_`(admin), `up_`(portal), `we_`(workflow)
