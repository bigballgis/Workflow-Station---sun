⚠️ Field-name cheat sheet (common mistakes to avoid):
- The field list must be "fieldDefinitions", never "fields"
- Primary key flag must be "isPrimaryKey", never "primaryKey"
- Descriptions must be "description", never "comment"
- Table display name must be "tableDisplayName", never "displayName" or "tableComment"
- Form bindings must be "tableBindings", never "fieldBindings" or "bindings"
- A binding references its table via "tableName", never "bindingTableId" or "tableId"
- Every form must have exactly one PRIMARY table binding unless the supplied requirements explicitly justify an ACTION form without persisted data
- A SUB binding must reference a SUB table and set foreignKeyField to an existing child-table field that references the PRIMARY table
- Every tableBindings.tableName and every tableRelations table/field reference must resolve to an item generated in tableDefinitions
- Express child-to-parent as ONE_TO_MANY with the parent as source and child as target; MANY_TO_ONE is invalid
- Use native formType values only: PROCESS for the overall process form, TASK for a user-task form, and ACTION for an action form
- Generate at most one PROCESS form; every TASK form must contain at least one stageBindings entry
- Every bpmn:userTask must be bound by exactly one TASK form whose stageBindings.stageId exactly equals the BPMN node id
- stageBindings.stageName must exactly equal the corresponding BPMN node name; include stageBindings.readOnly explicitly
- Never invent or emit a numeric formId in BPMN: form IDs are assigned by the database and the platform injects them from stageBindings after persistence
- VARCHAR fields must set length > 0
- IMPORTANT: length, precision and scale values must be JSON strings when present (for example, "length": "50"); use null when absent
- defaultValue must be a JSON string when present, including numeric defaults (for example, "defaultValue": "0")
- DECIMAL fields must set precision > 0 and scale > 0
- Every table must have at least one field with isPrimaryKey: true
- Use stable English snake_case identifiers for tableName, fieldName, formName, actionName and decisionKey; use human-readable English for display names and descriptions
- configJson must be either null or a JSON object, never an encoded JSON string. visibilityCondition must use the object structure and operators from schemaMetadata
- actionType must be one of the currently supported values listed in schemaMetadata.actionTypes; never restore a legacy integration type that is absent from that list
- Every action must contain a non-empty stageIds array, and every stageIds entry must exactly match an existing bpmn:userTask id
- Never invent or emit numeric actionIds in BPMN. The platform resolves generated ActionDefinition IDs from actionDefinitions[].stageIds after persistence and injects actionIds/actionNames into the matching user tasks
- ROLLBACK is a Flowable state-change action, not a normal sequence-flow outcome. Never add backward/rollback sequence flows or rollback_target_stage conditions to BPMN
