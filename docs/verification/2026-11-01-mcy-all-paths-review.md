### Major（已解决并重审）

1. useApplicationDetailDiagramParser.ts：MI 结束后将未执行出口整体标绿。
   - 反例：没有拒绝出口历史，Rejected 结束节点仍绿色。
   - 处置：My Request 复用 Task 的结束事件解析工具，按活动 ID 和真实状态；删除仅服务于旧推断的 MI 完成集合。相同标签的不同活动不再混淆。
   - 证据：五项失败测试转绿；同一实例真实截图灰/绿对照；最终三种分支与 SVG 颜色逐项对照。

2. useApplicationDetailDiagramParser.ts：REJECTED 终态的已进入 MI 容器仍 current。
   - 反例：全拒绝、没有活动任务，MI 外框仍橙色。
   - 处置：把 REJECTED 与 COMPLETED 作为已进入容器的正常终态；未进入的容器仍 pending，不添加业务列名判据。
   - 证据：新增反例先红后绿；原失败实例重开外框绿色、未执行任务灰色；两种 FU 全拒绝/全直接路径均通过。

3. TaskCompletionService / TaskHistoryAssembler：正常完成后的空 deleteReason 不能证明批准。
   - 反例：实际 Reject、引擎也走拒绝出口，但 Flow History 是 Approve。
   - 处置：完成事务内、权限校验之后记录 taskId 绑定的实际操作，历史优先读该证据；合法动作使用既有平台协议 APPROVE / REJECT / SUBMIT。没有按按钮名称或最后一笔交易的流程变量推测。
   - 证据：writer / reader 两项先失败后通过，额外五项验证协议操作/原备注/坏标记；14 份新请求的每个任务按 taskId 对照实际操作通过。
